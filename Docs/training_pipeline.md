# Training pipeline

`python -m src.pipeline.run` joins `Data/train.csv` to `Data/auxiliary_features/train_features.csv` by row order, and the same for the test files. The auxiliary files stay unmerged on disk. Install `requirements.txt` first. Run the commands from the project root.

```text
python -m src.pipeline.run evolve  --model mlp --features original,blocks --generations 4
python -m src.pipeline.run train   --model xgb --features original
python -m src.pipeline.run test    --model mlp
python -m src.pipeline.run predict --model mlp --out outputs/predictions/mlp.csv
```

`--model` is `ridge`, `xgb`, `mlp`, or `catboost`. `--features` is a comma-separated list of column names and presets: `original`, `blocks`, `spatial`, `coe`, `stocks`, `group_means`, and `all`. `--feature-file` is one name per line. `MONTHLY_RENT` is rejected.

For `evolve`, `--features` is the pool. The run starts from `models/<model>/default_genome.json` clipped to that pool, then reads `docs/logs` and proposes up to three mutants. It resumes `champion.json` only when that genome's features sit inside the pool and `--max-rows`, `--val-months`, and `--epochs` match the run that wrote the champion. A capped smoke champion is not the start of a later full run. Each mutant changes one of the feature subset, the preprocess gene, or the architecture. A mutant becomes the champion only when its search RMSE is at least 1% lower. `train` fits the given columns with the default preprocess and architecture. It replaces `models/<model>/best` and the champion only when the new search RMSE is lower. An equal or higher score leaves that snapshot in place. `--genome` is a JSON file whose `preprocess` and `architecture` objects overlay those defaults. The feature list still comes from `--features`. `ablate` tries each auxiliary column missing from `models/<model>/best` with that snapshot's own architecture. A column is promising when its search RMSE is at least 1% lower, except XGBoost and CatBoost, where any strictly lower search RMSE is enough. Those probes do not change the snapshot. The promising columns are then trained together once, and that combined set replaces the snapshot only when its search RMSE is lower. `finalize` retrains the features in `models/<model>/best` with a larger budget and writes `models/<model>/final`. The MLP uses widths 512, 256, and 128 for at most 200 epochs and stops after 15 epochs without a lower search RMSE. XGBoost uses depth 8 and at most 2000 trees, stopping after 50 rounds without a lower search RMSE. CatBoost uses depth 8 and at most 2000 iterations, stopping after 50 rounds without a lower search RMSE. Ridge keeps `alpha` 1. `predict` reads `final/` when that folder exists. `submit` rewrites `outputs/predictions/<model>_final.csv` from those weights and writes `outputs/predictions/<model>_refit.csv` after fitting the same final genome on every labeled row. The refit keeps the XGBoost round, the CatBoost iteration, and the MLP epoch already chosen on the search months, with early stopping off. `--refit-all` refits the champion genome, not `final/`. `submit` does not replace `best/` or `final/`. `use-all` fits every original and auxiliary column and writes `models/<model>/use_all_features`. XGBoost uses depth 6 and at most 2000 trees, stopping after 50 rounds without a lower search RMSE. Ridge uses `alpha` 1. The MLP uses widths 128 and 64 for at most 20 epochs and stops after 3 epochs without a lower search RMSE. That fit does not replace `best/` or `final/`.

Labeled months are cut in time. With `--val-months 3`, confirm is the last three approval months (`2025-01` through `2025-03` on the current train file), search is the three months before that, and fit is every earlier month. The preprocessor is fit on the fit months only. The `submit` refit is the exception: its preprocessor is fit on every labeled row. Confirm RMSE is written once after search stops and is not an acceptance signal. `predict` writes `Id,Predicted` in test-row order and does not change the genome. `--refit-all` retrains that frozen genome on every labeled month before predicting.

`--max-rows` keeps all three periods and stride-samples them. It is a smoke cap. Logs record the cap. Do not quote that run as a full-table result.

A feature set is stored at `models/<model>/ckpt/<feature_hash>/`. `features.txt` in that folder lists the sorted column names. `feature_hash` is the first 12 hex characters of SHA-256 over those names joined by newlines. Each fit is `runs/<run_id>/` and stores `genome.json`, `metrics.json`, `preprocessor.joblib`, and `model.pt` or `model.joblib`. The same full genome is not trained twice. Weights are gitignored. `docs/champion.json` points at the best search RMSE. `docs/design.md` restates the mutation rules and regenerates its champion, lineage, and prediction sections from the logs.

The fixed string cleanup lowercases text and turns `FLAT_TYPE` hyphens into spaces. Three columns ignore the categorical gene: `RENT_APPROVAL_DATE` is the number of months since `2021-01`, `BLOCK` is the fit-month mean rent of `TOWN|BLOCK|STREET` shrunk toward the fit-month global mean, and `FURNISHED` is 1 or 0 and is left out when the fit months have only one value. Each model's preprocessor selects the genome columns. Ridge and the MLP turn the other nominal fields into numbers with `onehot`, `ordinal`, `target`, or `bin`. XGBoost uses `native` categories, so a split can place any subset of the labels on the left. `target` is the fit-month mean rent of a level, shrunk toward that period's global mean. `bin` is one of 10 frequency bins, and an unseen level gets its own bin. Numeric impute is `median`, `mean`, or `zero`. Scale is `standard`, `none`, or `minmax`. The rare-level minimum is `10`, `30`, or `100` and is not applied to native categories. Group-mean columns are used as already written. Seed is `5228`.
