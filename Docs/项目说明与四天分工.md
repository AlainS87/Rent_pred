整理日期：2026 年 9 月 30 日。供四人小组讨论和执行。

本文根据课程说明页、Kaggle 比赛页面及已下载文件整理。“课程要求”和“建议方案”分别说明；尚未完成的分析不能作为已有结果写入报告。

## 1. 项目目标与课程要求

根据房屋属性及历史租赁记录，预测新加坡 HDB 的月租金 `MONTHLY_RENT`，单位为新加坡元。这是回归预测任务，Kaggle 使用 RMSE 评分，越低越好。

课程重点是理解数据、合理选择方法、解释设计决策、评估结果与局限，而不只是排行榜名次。

### 交付与评分

### 核心字段

| 字段 | 含义及处理注意点 |
|---|---|
| `RENT_APPROVAL_DATE` | 批准出租年月；用于时间划分和时间特征 |
| `TOWN` | 所属市镇；类别字段 |
| `BLOCK` | 楼栋号，可能包含字母，应保留为字符串 |
| `STREET` | 街道；需要统一大小写、空格及确认过的同义写法 |
| `FLAT_TYPE` | 房型，如 `4 room`、`4-room`，需统一表示 |
| `FLAT_MODEL` | 房屋型号；类别字段 |
| `FLOOR_AREA_SQM` | 面积，单位平方米 |
| `FURNISHED` | 是否带家具 |
| `LEASE_COMMENCE_DATE` | 租契起始年份，可结合租赁年份构造房龄代理特征 |
| `FEE` | 额外前期费用；不能未经依据自行计入目标月租金 |
| `MONTHLY_RENT` | 预测目标，仅训练集提供 |

### 已观察到、后续需要确认的问题

- 训练集首尾记录月份为 2021-01 和 2025-03；测试集首尾为 2025-03 和 2026-07。应进一步统计全部月份，重点检查时间边界。
- 房型存在 `4 room` 与 `4-room` 等写法差异；街道大小写也不统一。
- 网页预览统计显示测试集 `FURNISHED` 全为 `yes`、`FEE` 全为 0，需要在本地确认并对比训练集；不能现在就断言两列都应该删除。
- 课程说明写核心数据有 9 个属性、截至 2026 年 6 月，但实际文件有 10 个输入字段，且测试集包含 2026-07。应记录差异并查看 Errata／后续公告。
- 官方压缩包没有提交示例，现已由组员补充。示例数值只是格式参考，不能当作测试标签。

## 3. 建议的研究问题

1. 房屋基本属性能在多大程度上预测租金？
2. 加入地理位置和附近设施信息，是否带来稳定改善？
3. 模型预测较晚月份时表现如何，哪些地区、房型或租金区间容易出错？

让 EDA、特征工程、模型实验和报告围绕这些问题展开，避免仅罗列做过哪些操作。

## 4. 建议实施路线

### 第一步：先审查数据，再决定清洗

- 检查缺失值、字段类型、类别取值、数值范围和日期分布。
- 检查训练／测试的类别与分布差异。
- 统一房型、街道和楼栋写法，保留原始数据。
- 检查重复记录，但不要直接全部去重：相同月份、楼栋和房型可能对应不同出租单位。
- 检查异常面积和租金，但不要仅凭数值大就删除；结合地区、房型和业务含义判断。
- 每个清洗决策记录“观察到的问题—采用的方法—理由—受影响记录数”。

### 第二步：固定验证方案

由于训练和测试时间明显前后错开，优先考虑用较早月份训练、较晚月份验证。具体月份需在完整日期统计后决定。这是建议方案，不是老师指定的划分方式。

- 所有方法使用相同验证划分及 RMSE，保证比较公平。
- 后续可增加滚动时间验证，检查跨时期稳定性。
- 注意测试预测跨度较长，短期验证成绩不一定代表远期表现。
- 不要只依靠随机划分或反复查看 Kaggle 排名选择模型。
- 缺失填补、标准化、目标编码等参数只能从当前训练部分学习。
- 分组历史平均租金不能使用验证标签；未见分组需设回退策略。

### 第三步：建立简单基准

先完成训练集整体平均租金、地区与房型分组平均租金等基准，再尝试线性模型和树模型。进度报告阶段完成简单基准及少量比较即可，不必大规模调参。

### 第四步：逐组增加特征

| 特征组 | 建议内容 | 注意事项 |
|---|---|---|
| 基础属性 | 面积、房型、市镇、型号、年月 | 类别写法保持一致 |
| 房龄 | 租赁年份减租契起始年份 | 不要统一用当前年份；说明它是房龄代理量 |
| 楼栋信息 | 经纬度、规划区、区域、楼栋属性 | `MAX_FLOOR` 是整栋最高楼层，不是出租单位楼层 |
| 周边设施 | 最近地铁／商场／学校距离、范围内设施数量 | 检查坐标质量、距离单位及设施时间有效性 |
| 经济指标 | 按时间整理的 COE、可选股票指标 | 确定预测时可获取的信息，避免未来信息泄漏 |

建议先用标准化后的 `TOWN + BLOCK + STREET` 关联楼栋表。关联前检查键的唯一性，关联后检查行数、匹配率和失败原因，避免一条记录扩成多条。

优先做楼栋位置与周边设施，再考虑 COE，股票放后面。每次只增加一组特征并比较结果，以说明改进来自哪里。不能把规划中的地铁站一律视为租赁当时已经运营。

### 第五步：解释结果并保证可复现

- 按月份、地区、房型及租金区间查看误差，解释失效情形。
- 区分相关性与因果关系。
- 记录数据版本、划分、随机种子、参数、特征组合和结果。
- 提供运行顺序和依赖说明，保留原始数据与处理结果的区别。
- 最终提交保留 sample submission 的编号及原始测试行对应关系，只替换预测列；检查缺失值、无穷值、列名与行数。
